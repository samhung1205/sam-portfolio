回專案列表 Engineering Case Study

YOLO System

一支 UI、業務邏輯與 SQL 全部寫在同一層的 PySide6 桌面程式， 在不停機、不重寫的前提下，逐步變成桌面版與 React Web 共用同一組 FastAPI 的偵測平台。

角色
個人專案：架構、後端、Web 前端、桌面端重構
核心技術
FastAPI · SQLAlchemy · Alembic · React · PySide6 · LangGraph · Ultralytics YOLO · MySQL
狀態
開發中。後端、Web、桌面主流程可用；容器化與部署尚未完成
原始碼
The Problem

問題不是「偵測不準」，是「只剩一種改法」

這個系統原本能用：登入、使用者管理、YOLO 影像偵測、AI 對話都跑得起來。 問題出在它只有一層：PySide6 的 UI handler 直接執行 SQL、直接載入模型、 直接呼叫外部模型 API。任何一個需求都得回到那一層去改。

  • UI 就是資料層。視窗事件處理函式裡直接組 SQL 字串送進 MySQL，沒有任何中介。
  • 密碼以明文存在資料庫。沒有雜湊，登入就是字串比對。
  • 金鑰與連線字串寫死在原始碼裡。模型 API key 與 DB 連線資訊都直接躺在檔案中。
  • SQL 用字串格式化拼接外部輸入。注入風險是結構性的，不是個別疏漏。
  • 狀態靠全域物件。視窗之間靠一個全域 class 互相持有引用。
  • 只有一種客戶端。想要一個能展示、能遠端使用的 Web 版，等於整套重寫。
Constraints

重構的邊界條件

  • 桌面版必須全程可用。它是既有的、有人在用的程式，不能為了重構先讓它壞掉幾個月。
  • 一個人做。沒有可以平行推進的第二條線，所以每一步都要能單獨驗證、單獨回頭。
  • 模型權重不進版控。.pt 檔太大，部署與相容性得靠設定與註冊機制處理，不能靠「檔案剛好在」。
  • Agent 相關依賴很重。LangChain / LangGraph 安裝失敗不能連帶讓整個 API 起不來。
Architecture

架構演進

真正的改變只有一句話：把「誰可以直接碰資料庫、模型與外部 API」從 UI 手上拿走。 客戶端從此只認得 HTTP，後端成為唯一持有資料與金鑰的地方——Web 版之所以能加上去， 是因為它不需要再實作一次任何業務邏輯。

Engineering Decisions

五個關鍵決策

先立 API 邊界，再一支一支搬客戶端

問題
整包重寫風險太高，而且重寫期間桌面版會長時間不能用。
決策
先把 FastAPI 後端做起來，桌面端逐個功能改成呼叫 API：先 auth 與使用者管理，再 detection，再 chat；每一段都保持桌面版可執行。Web 前端是在邊界穩定之後才加上去的。
為什麼
API 邊界一旦立好，「再加一種客戶端」就從重寫變成純前端工作，因為業務邏輯只實作在一個地方。
取捨
過渡期同時存在新舊兩條路徑，得自己記得哪些還沒搬；webcam 與 RTSP 到現在仍走 legacy 本機推論。桌面端的 HTTP client 依操作類型分開設定 timeout（推論、上傳、SSE 各不相同），否則單一 timeout 會在長任務中途把連線砍斷。

認證與機密：從明文到 bcrypt + JWT，並讓錯誤設定在啟動時就爆

問題
密碼明文儲存、金鑰與 DB 連線硬編碼在原始碼裡。
決策
密碼改用 bcrypt 雜湊，登入改發 JWT；所有機密移到 .env 並提供 .env.example。後端啟動時檢查 SECRET_KEY 是否仍是內建預設值。開發環境印警告，APP_ENV=production 則直接拋錯拒絕啟動。
為什麼
「忘記設定」是最容易發生也最貴的失誤。與其寫在文件裡提醒自己，不如讓程式在錯誤的環境下拒絕啟動。
取捨
明文舊密碼無法遷移成雜湊，既有帳號必須重設密碼。users.email 在資料表層仍允許 NULL 以相容舊資料，新的註冊流程才強制填寫。

偵測結果圖不能只靠登入保護

問題
API 用 Authorization header 驗證，但 <img> 與下載連結送不出 header。若把結果圖直接開成公開靜態檔，等於任何人猜到路徑就能看別人的偵測影像。
決策
API 回傳的不是裸路徑，而是帶 HMAC 簽章與到期時間的 /static/... URL。取檔時後端驗簽、驗到期、正規化路徑擋掉 ..，再回查該檔案屬於哪個 detection task，確認請求者是擁有者或 admin。
為什麼
簽章 URL 讓瀏覽器原生的 <img> 能直接用，同時保留每一次存取的授權檢查；短時效讓外流的連結會自己過期。
取捨
URL 會過期，前端拿到後不能長期快取或存下來當永久連結。

模型用註冊表控管，不讓客戶端指定檔案路徑

問題
系統要能切換多個 YOLO 權重；但只要 API 收「路徑」，就等於開放讓外部載入任意檔案。而且部分權重是用自訂模組訓練的，PyTorch checkpoint 會記錄當初的 Python module 路徑，載入時找不到就會直接失敗。
決策
後端維護一份允許清單，每個 checkpoint 都登記 key、架構、類別對照與預期的 SHA-256。客戶端只能送 key。載入前比對檔案指紋，不符就把該模型標成不可用並附上原因；不相容的 OBB 權重直接標記為停用並寫明理由。自訂模組則在載入前，把 checkpoint 需要的歷史 module 路徑指回 repo 內的原始碼。
為什麼
把「哪些模型可以跑」變成程式碼裡的顯式清單，而不是檔案系統的巧合。指紋比對讓權重被換掉時會被擋下，而不是安靜地跑出不同結果。相容層則避免了「把檔案複製進 site-packages」這種裝完就忘、換台機器就壞的作法。
取捨
新增模型必須改程式碼並更新指紋，不能只丟檔案進資料夾。這是刻意的：每一個能跑的權重都應該被審過一次。

Agent 層唯讀、可降級，而且有一套 eval 盯著它別亂講

問題
要讓使用者能用自然語言問「這次偵測結果代表什麼」，但 LLM 一旦能寫入資料就很難界定風險，而且它很容易把沒看到的細節講得像真的。
決策
用 LangGraph 做一層 supervisor（分類意圖 → 呼叫工具或子代理 → 組答案 → 錯誤處理），工具全部唯讀，不提供 create／update／delete；非 admin 強制只能查自己的資料，admin 專用工具在函式開頭硬檢查權限。Agent 不能觸發 YOLO，只能讀既有紀錄。LangChain 相關套件一律 lazy import，缺套件或缺金鑰時回 fallback 訊息而不是讓 FastAPI 起不來。
為什麼
唯讀邊界讓「agent 出錯」的最壞情況止於一段錯誤的文字，而不是資料損毀。lazy import 則讓這層重依賴不會變成整個後端的單點故障。
取捨與驗證
自然語言輸出沒辦法靠單元測試斷言，所以另外寫了一組 component eval：20 個手工設計的案例（零物件、低信心度、失敗任務、信心度邊界值、缺欄位等），檢查回答有沒有捏造類別、有沒有引用不存在的信心度數值、該提醒人工複核時有沒有提醒。repo 內committed 的那次執行（deepseek-chat，2026-07-08）在 grounding 與捏造視覺細節這兩項全數通過，過度觸發複核的比率為 8.3%。 這是單一 provider、20 個案例的一次執行結果，用途是回歸偵測，不是通用品質保證。
System Today

重構後的系統做得到什麼

兩種客戶端共用同一組 API，因此以下能力在桌面與 Web 上是同一份實作。

偵測

  • 單張影像同步偵測
  • 影片偵測，背景任務產出結果影片與預覽圖
  • 多圖與資料夾批次分析
  • 偵測歷史查詢

模型

  • 七個可選權重，含自訂模組變體
  • 每次任務記錄模型 key、SHA-256 與類別對照

對話與 Agent

  • 多 provider 對話（OpenAI／DeepSeek／Ollama／mock）
  • SSE 串流，桌面與 Web 共用同一份協定
  • 七種 agent 模式，報告可匯出

帳號與資料

  • JWT 認證，使用者與 admin 權限分離
  • 10 個 Alembic migration 管理 schema 演進
Trade-offs

還沒做完的部分

以下都是已知並且刻意延後的，不是被忽略的。

  • 影像偵測仍是同步呼叫。單張圖片可以接受，但這條路徑遲早要跟影片一樣改成非同步任務。
  • 影片偵測用 BackgroundTasks，不是真正的 job queue。沒有進度百分比、不能取消，桌面端目前靠輪詢等待完成。
  • 影片只保存預覽幀的物件列表，不是每一幀的結果。
  • webcam 與 RTSP 仍走 legacy 本機推論路徑，尚未後端化。
  • Web 的一般對話頁還沒接上 SSE（Agent 頁已經接了）。
  • 容器化、部署與 CI 尚未完成，目前仍是本機執行。
What I Learned

做完之後的三個體會

  • 邊界比技術選型重要得多。真正讓 Web 版變成可行的不是 React， 而是「業務邏輯只實作一次」這件事先做到了。
  • 安全問題大多是預設值問題。明文密碼、硬編碼金鑰都不是難修的技術問題， 難的是讓它們不會再回來，所以最後選擇讓錯誤設定在啟動時就失敗，而不是寫在 README 裡提醒自己。
  • 文件會落後於程式碼。整理這頁時發現架構文件仍記載 agent streaming 是 placeholder， 但它其實已經實作完成，文件索引也還指向一份不存在的檔案。下一輪要做的是讓文件檢查進到流程裡，而不是靠記得。
